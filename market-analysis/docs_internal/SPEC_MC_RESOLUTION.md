## 4. 修法

### Part A — 报出原始计数与不确定度（零额外算力）

**存 `(X, n_used)` 原始 MC 计数，不存 SE**（审查 B4/S-f）：
- 自助：`X` = 穿零计数（`min(frac_le, frac_ge)` 对应的那个），`n_used = B − n_dropped`
  —— **分母必须是 `n_used` 不是 `B`**，而 `n_dropped` 现在被 autodiscovery 丢掉了。
- 置换：`X` = `count(null >= real)`，`n_used = N_PERM`。
- 理由：`p_floor` / SE / 重抽全都能从 `(X, n)` 导出，天然"与 B/N 同源"（比存 SE 结实），
  而且退化情形（X=0）**显式说"没有"**，不会编出一个 `SE=0`
  —— 这是 `_sign(nan)` 那次的同一条教训。

派生字段：
- `p_floor`：自助 `2/n_used`；置换 `1/(n_used+1)`。

  "面向读者的措辞用概率，不用 SE"。再发一个没人消费的 SE 字段只是噪声。

  精确式 0.01936、R1 用的 `sqrt(2p/B)` 给 0.02236、高估 16%）——

### Part B — 按「改判概率」加算，不按「离阈值几个 SE」

#### B-1 理论框架（换掉 R1 的错框架）

**R1 的论证错了**：R1 称"带 +1 平滑的 MC p 值 `(1+X)/(1+B)` 在 H₀ 下精确有效，对任意 B 成立"。
这对 `perm_test` 成立（观测统计量与 N 个置换值在 H₀ 下可交换 → 秩均匀、"+1"数的是观测值自己），
但**对 `block_bootstrap_diff` 不成立**：它不是置换检验，是**从经验分布重采样 + CI 反演**。
自助分布近似的是**估计量在观测值附近的抽样分布**，不是 H₀ 下的零分布；
观测统计量**不是那 B 个抽样中的一个**，所以没有可交换性、没有"观测值占一格"的对象。
而 **97/148 条候选（除 calendar 的 51 条）走的正是自助**，且该函数被 **8 个模块**共用 → R1 的许可证对大多数候选无效。
给一个自己不具备的保证贴标签，正是本项目定义的最重缺陷类型。

**本版换成 resampling risk 口径**（Besag & Clifford 1991；Gandy 2009 *uniformly bounded
resampling risk*；多重检验版本 = Gandy & Hahn 的 **MMCTest / QuickMMCTest** —— 那篇处理的
正是"MC p 值 + step-up 多重校正 + 自适应分配算力 + 第三类输出 undecided"）。
问题从「p 还有效吗」改成「**有限 MC 得到的判定，和 B=∞ 的理想判定一致吗，不一致的风险多大**」。
在这个口径下：
- 只给"MC 噪声可能改判"的候选加精度 = **定义上正确**的算力分配，不需要任何关于 p 值有效性的新主张；
- 远离判定边界的不加算不引入偏差 —— 它们的**判定**在噪声下本来就不会变；
- 达不成一致的如实标 unresolved —— 这正是 MMCTest 的第三类输出。

**诚实边界（必须写进方法论页，别让读者以为被覆盖了）**：即使 `perm_test`，
"精确有效"说的是**对置换零分布**精确；把星期/月份标签在自相关、异方差的收益序列上置换，
置换零分布是否等于科学零假设是**另一件事**（本规格不动它）。

#### B-2 判据：改判概率，不是 `z = |p − c_i| / SE`

**R1 的 `z` 判据对 step-by 程序是错的度量**（审查 B2，三条证据我已复核）：

1. **在关键区间退化成恒真**。两个估计器在下限附近都有 `SE ≈ p`，于是 `z ≈ |p−c|/p`，
   而 c₁..c₁₄ 全在 0.001 的 0.12×–1.7× 之内 → `Z=2.0` 把**全部 14 条拒绝项一条不漏**
   地选中（线上实测 18 条）。那不是"边界带"，那是"全选"。
2. **`c_i` 在并列组内由枚举顺序决定，没有统计含义**。`bh_reject` 用稳定排序 →
   并列组内 rank = 原始下标。把输入顺序打乱后 `santa_sp500` 的 `c_i` 从 0.000969 变
   0.001454、`z` 从 0.03 变 0.46。拒绝集不变（§2.5），但 R1 要求把"余量多少 SE"
   写进 `mc_unresolved_reason` → **会发布一个取决于枚举顺序的数字**。
3. **会把全站最稳的一条永久标成"分辨不了"**。实测：`p5_h1_nasdaq` 在 **B=20000 下仍
   p=0.000000**（零穿越）→ `p_at_floor` 恒为真 → 按 R1 被永久标 `mc_unresolved`。
   可它 rank=1、`k=14`，是**最不可能被噪声改判**的一条（§2.2：84.3% 仍在名单上，7 条里第三稳）。
   给最强的证据挂"无法分辨"的牌子 = **把证据说得比实际弱**，同样是最重缺陷类型，只是方向相反。

**判据换成判定稳定性**：

```
pass 1：全部候选按现行 B/N 算，存 (X, n_used)            ← 成本不变
        ↓
重抽 K 次（纯算术，秒级，不重跑任何自助/置换）：
    θ* ~ Beta(X+½, n−X+½)；X* ~ Binom(n, θ*)；重建 p*；
    **重跑 by_reject + adjudicate** → 每条的「改判概率」
        ↓
加算集 = { 改判概率 > P_REFINE } （天然覆盖 X=0：后验最宽）
        ↓
pass 2：选中者按 REFINE_FACTOR=10 的 B/N 重算，**只加算一次**
        ↓
重抽一次 → 仍 > P_UNRESOLVED 的标 mc_unresolved
```

这个判据：天然覆盖 `p_at_floor`、天然**不受并列顺序影响**、天然对 step-up 正确
（它直接模拟 step-up）、天然覆盖 modern 判定（同一次 `adjudicate` 里）。

常量 `P_REFINE` / `P_UNRESOLVED` / `K` **不许凭感觉定**：建造者必须打印实际选中条数
并写进 commit（§9-3）。参考：`P_REFINE=5%` 时线上约 18 条（实测 pass-2 成本 +67s）。

**🔴 陷阱（保留 R1 的 D9，它是对的）**：加算后**一律采用 pass-2 的 p**，
**绝不**取 `min(pass1, pass2)` 或"更显著的那个"。
理由（本版修正）：两次抽样取极值**不再是对理想 p 的一致估计**，且取哪个依赖观测结果
—— 这会把 p-hacking 藏进实现细节。见 D9 / S7 / T6。

### Part C — 分辨不了就说分辨不了（**对称**披露）

新增 `mc_change_prob`（改判概率）+ `mc_unresolved` 布尔 + `mc_unresolved_reason`。

**判断点（已定）：绝不新增 `verdict` 取值。** 三条依据（全部已核实）：
`verdict` 进 append-only `autodiscovery_log.csv`（加取值让历史行不可比）；
`flicker.py` 靠 `verdicts[i] != verdicts[i-1]` 数横跳（会污染那条线）；
`knowledge_base.decide` 写死 `adj == "survive"`（加取值会**静默停掉晋升**而不报错）。

**披露必须对称（审查 B6）**：`survivors_live.build()` 第一行就过滤
`verdict == "survive"` → `unstable`/`stability_note` 只挂得到 7 条。
但 §2.2 里改判概率最高的 8 条中有 **4 条是 faded/dead**，而 `BTC_mom20_neg`（现 dead）
有 10% 概率是 survive。**一条"其实可能存活"的 dead，和一条"其实可能已死"的 survive，

### Part D — 守门（本规格真正的产出）

**R1 的慢查是假绿（审查 B8）**：R1 写「按 N 个种子重跑 `adjudicate`」——
但 `adjudicate` **没有种子参数、也不算 p**，它只消费算好的 p。按字面实现会 N 次得到
同一个答案、**恒报 0 条改判**，然后 §9 的"修复后应显著下降"看起来完美达成。
这正是 `fe8af0a` 的教训：**"我跑了一次是绿的" ≠ 验证过，还得问它到底在测什么。**

**本版改成两层：**

- **快测（pytest，秒级）**：用 Part B 的重抽（纯算术、不重跑统计）对产物断言 ——
  每条要么**改判概率 ≤ P_UNRESOLVED**，要么**已标 `mc_unresolved`**。
  二者皆非 = 一个悄悄落在噪声里的裁决 → 红。
  **这才是"当初若存在，第一天就会抓到"的守门**，而且能进 CI。
  必须豁免 `recent_powered=False` 的 6 条、以及"对裁决无影响的判定"（§2.3、审查 S-e）。
- **慢查（`tools/mc_stability_audit.py`，离线工具、不进 CI）**：真换种子重跑
  **`compute_results`**（不是 `adjudicate`），N=13 约 **26 分钟**（119s×13）。
  规格必须把"必须重跑 compute_results""不进 CI"写在工具 docstring 里。

## 11b. 落地后仍需盯的（本规格范围内）

- **S6 的余量很薄，且测量本身对并发负载极敏感**（独立审实现 S3）：
  同一份代码，作者本机测 pass-1 **125s**、审查者机器测 **240.5s**（各自跑 2–3 次都很稳），
  而 `block_bootstrap_diff` 的**调用次数两边完全一致（都是 521 次）**、只是均次 0.130s vs 0.281s
  —— 块自助是内存带宽敏感型，审查者机器上另有两个 python 进程。
  **所以"3.3 分钟"只是本机单次测量，谁对谁错无法断定。**
  → 已把 `seconds_pass1` / `seconds_pass2` 写进 `mc_stability`，**以 CI 实测为准**；
  S6 的分母口径明确为**两遍合计**（本机 3.3 分钟 / 审查者机器 6.1 分钟，后者已超门槛）。
  另：**S7（pass-2 重复算展示窗，实测占 pass-2 的 19%）刻意不做** ——
  它是纯优化，而修它要给 `adopt_pass2` 加合并步骤，会搅浑刚加固的 D9 红线，
  正是规格自己警告的那种"顺手优化"。登记在此，不当没看见。
- **原 S6 条目**：本机 3.4 分钟 vs 门槛 4 分钟，而 CI 机器可能更慢，且
  **F2（block 放大）会同时改变成本结构**（线上 `block=1` 那 86 次调用占自助耗时 23%）。
  → C2+C3 上线后**必须看 CI 实测的 run_all 总时长**；若逼近 12 分钟预算，
  先调 `P_REFINE`（加算集变小）或 `REFINE_FACTOR`，别直接砍度量。
- **加算集规模随数据漂移**：16 条是今天的数。P_REFINE=0.05 是个阈值、不是上限，
  S2（>40 条即停）是那道保险。产物里发 `mc_stability.n_refined`，逐轮可见。
